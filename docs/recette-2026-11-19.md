## Isolation

Avec le jeton d'un utilisateur A, tous les appels visant l'espace ou la base d'un utilisateur B
(`describe_base`, `create_table`, `search_knowledge`, `list_collaborators`, `get_process_map`) sont refusés
(« no permission »), et `list_workspaces` ne montre que l'espace accordé.

## Écarts relevés et traitement

| Constat | Traitement |
|---|---|
| Les formules exigent des identifiants de champ, pas des noms | Skills `tblflow-formules`, `tblflow-champs-et-liens` corrigés |
| Cumul (`rollup`) et recherche liée (`lookup`) non créables par le connecteur | Dit explicitement ; à créer dans l'interface |
| Le tri (`sort`) de `list_records` échoue (erreur `orderBy`) | Skill : ne pas l'utiliser ; **défaut du serveur à corriger** |
| Opérateurs de date « avant/après » absents, case à cocher limitée à `is` | Table des opérateurs vérifiés dans `tblflow-filtres-vues` |
| Réponse d'`update_records` : valeurs calculées périmées | Skill : relire après écriture |
| `create_table` ajoute trois lignes vides | Skill : les supprimer (aperçu, accord, confirmation) |
| `groupBy` renvoie des clés de groupe opaques | Skill : un appel par catégorie avec filtre |
| Zéro initial perdu à l'import en nouvelle table | Skill : contournement vérifié (table avec champ texte, puis import en ajout) |
| Import asynchrone (`queued`) | Skill : attendre puis vérifier |

## Ce qui n'a pas été vérifié

- Exécution réelle d'une automatisation ou d'un agent exposé.
- Résultats non vides de `search_knowledge` et de `get_process_map`.
- Types de champ autres que ceux listés comme « vérifiés » dans `tblflow-champs-et-liens`.
- Comportement de la CLI TblFlow.
